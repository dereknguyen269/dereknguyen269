## The idea behind the redesign

A developer profile should answer three questions quickly:

1. What does this person build?
2. What are they working on now?
3. Where can I try the work or learn more?

That is the standard I used for the update. The page now leads with the kind of work I enjoy most: developer utilities, backend systems, and small internet products that remove friction from ordinary workflows.

The profile also includes live GitHub statistics and contribution graphs. Those widgets are not there to turn engineering into a scoreboard. They are a living trail of experiments, maintenance, writing, and shipping.

## TOOlover: fewer interruptions, more building

The main product focus is **[TOOlover](https://thetoolover.com)**, a free browser-based toolbox for developers.

The problem is familiar. You need to format a JSON payload, compare two text snippets, inspect a JWT, test a webhook, generate a secret, preview Markdown, or run a quick transformation. None of these tasks is especially difficult, but each one can break your flow. You open a new tab, search for a tool, wonder whether it is safe, copy data between places, and eventually forget what you were doing.

TOOlover is designed for that moment.

It brings together practical tools for:

- JSON formatting, validation, conversion, and diffing.
- Webhook testing, payload generation, and temporary request inspection.
- JWT inspection and secure secret or password generation.
- Markdown, HTML, and text preview and transformation.
- Lightweight simulations for topics such as rate limiting and caching.

The product is free to use and does not require signup. The goal is not to create another complicated platform. It is to make the small, repetitive parts of development disappear into a fast, dependable utility layer.

**[Open TOOlover and try a tool →](https://thetoolover.com/apps)**

## What comes next

I’m continuing to improve the product around the same principle: remove tiny developer frictions without adding ceremony.

That means better tool discovery, clearer workflows, useful defaults, and more utilities that work directly in the browser. It also means paying attention to the details that make a small product feel trustworthy: predictable behavior, readable output, privacy-conscious handling, and documentation that respects the user’s time.

Alongside TOOlover, I’ll keep publishing practical notes about software engineering and system design here. The topics will range from architecture and developer productivity to the lessons that emerge while building and maintaining small products.
